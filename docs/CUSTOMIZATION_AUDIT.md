# Customization source audit

22 October 2026. Source baseline includes existing uncommitted animation, palette, carousel and product work. This audit does not attribute that work to the new roadmap. No code reset, live content migration or deployment is part of the audit. The matrix records the initial source snapshot; product and motion work continued concurrently during F1 (including collection/default chart assignment and gallery state fixes). The regenerated reference reflects latest schemas; re-inspect affected code before each future chunk rather than treating a snapshot finding as permanent.

## Source and documentation map

- `theme/` is the deployable native Shopify theme: 28 section Liquid files, two theme blocks, 26 snippets, two layouts and 12 templates (11 JSON plus gift-card Liquid). Header/footer use JSON section groups; cart drawer is a static section. `config` defines settings and merchant/preset values; `locales` holds storefront and schema translations.
- `src/entries/global.ts` installs shared services and eager shell elements, then registers lazy section components. `product.ts` registers the product UI and its stylesheet. No React/Vue storefront exists. The React/Framer examples in `infomation/example componenets/` are reference material, not executable theme modules or permission to copy external code.
- Vite discovers page entrypoints, emits flat content-hashed JS with stable entry CSS and stages into `.build`. `sync-assets.mjs` owns only files recorded in `assets.owned.json` and generates `nk-assets.liquid`. Never hand-edit generated files. `watch.mjs` coordinates the build watcher and sync. Hashed entry URLs intentionally omit query versions to prevent duplicate module instances.
- Tailwind v4 is configured in `src/styles/tailwind.css` using the Vite plugin, `@source` Liquid/TS discovery and `@theme inline` token mapping. There is no Tailwind JS configuration to replace. `global.css` imports reset/base/component styles, then Riviera and hero refinements. Several component CSS files are both globally imported and imported by their lazy module; measure the emitted graph before changing loading.
- `README.md` explains build/deploy conventions. `UPDATES.md`, `update.md`, `docs/PRODUCT-SYSTEM-AUDIT.md`, `docs/SIZE-CHART-SETTINGS.md`, `docs/STOREFRONT-ARCHITECTURE.md`, `SCROLL_ANIMATION_PLAN.md` and existing `CUSTOMIZATION.md` record previous implementation and evidence. Older descriptions of sticky buy/accelerated buttons are superseded by current product source and the product audit.
- `infomation/00–10`, `master-plan/00–14` and evidence files describe design, component rewrite, commerce, editor and release intentions. `references/` contains research, and `owner-questionnaire/` contains unanswered discovery templates. Treat proposed settings/business claims as proposals. Do not block authorized theme work on old questionnaire approval language. Preserve Skeleton attribution in `docs/LICENSES/`.
- `package.json` pins Shopify CLI 4.9, Vite 8.3, TypeScript 6, Tailwind 4.3, GSAP 3.15, OGL and Vitest/happy-dom. `tsconfig.json` uses strict DOM/bundler typing. Existing unit tests cover commerce sequencing, search, product, overlay, section replacement and motion. `check-json` parses JSON; it is not a comprehensive schema behavior validator.

## Theme blocks, snippets and design primitives

- `theme/blocks/group.liquid`: accepts `@theme`, row/column presets, vertical alignment and one-axis padding. Flex never wraps and `overflow:hidden` can clip long content/focus. Needs gap, wrap and mobile stacking before being advertised as a general builder container.
- `theme/blocks/text.liquid`: plain text/style/alignment, title/subtitle/normal choices and one preset. Uses a div, so a title appearance is not a semantic heading; add a dedicated heading block instead of silently migrating existing content.
- Render-only media: `image` supplies CDN widths/fallback; `product-media` handles product images/video/external media/models; `icon` supplies SVGs. Reuse these with deliberate sizes/priority/fit rather than duplicating image markup blindly.
- Type/effects: `reveal-heading`, `letter-swap`, `hero-button`, `scene-attributes`. Shared hero CTA has special label-roll markup and styles; general button reuse must preserve accessibility and purchase button semantics.
- Commerce: `product-card`, `price`, `carousel-product-data`, `product-option-links`, `product-siblings`, `swatch-color`, `product-measurements`, `size-chart`, `measurement-chart-rule`, `line-item`. Product swatch color literals represent products, not brand colors; do not replace them with the global accent.
- Navigation/results: `facets`, `pagination`, `nav-drawer`, `menu-promo`, `search-modal`. Shared rendering and services already exist. Some search/modal IDs assume one shell; result/product rewriting isolates fetched markup.
- Infrastructure: `css-variables`, `nk-config`, generated `nk-assets`, `meta-tags`. Keep tokens/JSON/routes/output responsibilities separate. All runtime JSON values must pass `json`; user strings in attributes must pass `escape`.
- Global design: scheme colors/derived accent family, three font pickers/body size/heading case, width/section rhythm/radius, image ratios/fit/badges/sizes, product selection/inventory policy, five chart rules, cart action/note/source, motion and social links. Riviera deliberately hardcodes font weights/tracking/button treatment; classify and migrate these by F3/F4, not in F1.
- Current global style presets: Riviera and Quiet in `settings_data.json`. Schema defaults differ from saved merchant values (for example schema spacing 72px vs saved 112px). Document schema defaults separately from current content.

## Validation boundaries

Source audit and local tests establish structure and known code paths. Prior screenshots/reports remain historical evidence. New roadmap acceptance must record actual tests for each changed chunk. At audit baseline: 84 unit tests, TypeScript, JSON and Theme Check pass. Native Theme Editor persistence/reordering, physical-device accessibility/performance, high-variant/app/market fixtures and live form submissions require their own sessions; none is inferred from passing local checks.

The roadmap assigns fixes before expanding the affected components. No new framework, cart engine, generic page-builder store or universal animation abstraction is justified by this audit.

## F2 follow-up

Media with text now adopts the shared presentation contract: `section-presentation.liquid` renders
local width/padding inputs, base CSS consumes them, and the existing color scheme remains local.
Long-heading overflow was reproduced and fixed in this section's own grid. The initial matrix
above remains the audit snapshot; current settings and actual validation are documented in
`CUSTOMIZATION.md` and the F2 roadmap checkpoint. No other section opts into this contract yet.
